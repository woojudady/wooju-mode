# 우주모드 v4.0 — Claude Code 훅 연동판

우주모드 v4.0 규칙(`wooju_infinite_prompt.txt`)을 **Claude Code 훅**으로 강제하는 구현입니다.
프롬프트를 붙여 넣는 방식은 그대로 쓸 수 있고, 이 폴더는 Claude Code(CLI)용 추가 구성입니다.

- `wooju_mode.py` — 훅 본체 (주입 · 표시 전 검토 · 끝내기 전 검사 · 설치 · 집계)
- `test_wooju.py` — 오프라인 시험 (검토자를 실제로 부르지 않는 가짜 판정으로 돈다)

---

## 1. 왜 훅으로 바꿨나

**프롬프트는 모델이 잊으면 안 돈다.**
우주모드는 원래 챗봇의 시스템 프롬프트입니다. 짧은 대화에서는 잘 지켜지지만, Claude Code처럼
도구를 수십 번 부르는 긴 작업 세션에서는 규칙이 흐려집니다. 그리고 지켰는지 **아무도 확인하지 않습니다.**
라벨(🔸🔹⚪❌)을 달아 놓고 근거 파일을 실제로는 열지 않았거나, 숫자가 도구 출력과 다르거나,
`범위:` · `모드:` 줄을 빠뜨려도 그대로 화면에 나갔습니다.

Claude Code는 **훅**(사용자 메시지를 받을 때, 답을 화면에 보이기 전, 응답을 끝내려 할 때 등)으로
매 단계에 프로그램을 끼워 넣을 수 있습니다. 그래서 규칙 중 **기계가 확인할 수 있는 부분**을 골라
"기억에 맡기는 규칙"에서 "통과해야 나가는 규칙"으로 바꿨습니다.

훅이 판정하는 건 참 · 거짓이 아니라 **형식과 추적 가능성**입니다.
- 🔸 라고 한 근거를 이 세션에서 실제로 열어봤나
- 🔸 줄의 숫자가 이 세션의 도구 출력 · 사용자 글에 실제로 있나
- 웹 근거가 서로 다른 도메인 3개 이상인가 (못 채우면 `출처 부족:` 으로 밝혔나)

코드 작업 환경에 맞춰 원문에서 바꾼 점도 있습니다.
- **'A 모드 = 무조건 웹 검색'** → 근거를 `파일:줄` · 명령 · URL · 이미지로 넓혔습니다. 코드 질문의 1차 근거는 웹이 아니라 파일입니다.
- **페르소나(말투) 규칙**은 기계 검사가 안 되고 할루시네이션과 무관해서 뺐습니다.

원문의 W∞-Lock 4계층과는 이렇게 대응합니다.

| W∞-Lock 계층 | 훅 구현 |
|---|---|
| Layer 0 — Immutable Priority Lock | `inject`: 매 메시지마다 규칙 요약을 컨텍스트에 다시 넣는다 |
| Layer 1 — Procedural Enforcement | `check`(Stop): 형식 위반 · 반려된 답을 끝내지 못하게 막고 다시 쓰게 한다 |
| Layer 2 — Mode Preservation | 모드 B 인데 도구를 썼거나 숫자 · 파일 주장이 있으면 지적 |
| Layer 3 — Response & Recovery | `display`(MessageDisplay): 화면에 나가기 전 검토자가 근거를 대조, 반려되면 `Revised:` 로 전체 재작성 |

## 2. 어떻게 동작하나

### 훅 세 개

| 훅 이벤트 | 명령 | 하는 일 |
|---|---|---|
| `UserPromptSubmit` | `wooju_mode.py inject` | 규칙 요약을 매 메시지에 주입 · 질문 시각 기록(반려 횟수를 질문 단위로 세려고) |
| `MessageDisplay` | `wooju_mode.py display` | `범위:` · `모드:` 로 시작하는 최종 답은 **다 써질 때까지 숨기고** 검토 → 통과면 전체 표시, 반려면 안내 한 줄 |
| `Stop` | `wooju_mode.py check --warn` | 형식 검사(경고) + 같은 답의 검토 판정을 받아 1번째 반려면 **응답 종료를 막고(exit 2)** 다시 쓰게 함 |

### 형식 검사 (Stop, 기계 검사)
- `범위:` 줄, `모드: A|B|C` 줄이 있는가
- 모드 B 인데 이번 턴에 도구를 썼거나 숫자 · 파일 주장이 있지 않은가
- A · C 에 라벨이 하나라도 있는가, A 는 `검증:` 줄, A · C 는 `결론:` 줄이 있는가
- 세 자리 이상 숫자가 든 줄에 라벨이 있는가 / ⚪ 줄의 세 자리 숫자에 계산식(`=`)이나 `가정:` 이 있는가
- 🔸 · 🔹 줄에 `[근거: …]` 가 있는가, 도구를 한 번도 안 쓰고 🔸 를 쓰지 않았는가
- `[근거: 파일:줄]` 을 이 세션에서 실제로 열거나 grep 했는가
- 🔸 줄의 숫자가 이 세션 도구 출력 · 사용자 글에 있는가 (이미지 근거는 대조 생략)
- 근거 URL 도메인을 이 세션에서 열람했는가, 도메인이 3개 이상인가

### 표시 전 검토 (MessageDisplay, 검토자)
`claude -p` 로 **별도 Opus 검토자**를 띄웁니다. 검토자는 `Read` · `Grep` · `Glob` 만 쓸 수 있고 파일을 고치지 못합니다.
1. 반려 뒤 다시 쓴 답이면 `Revised:` 줄이 있는지, 앞 지적이 실제로 고쳐졌는지
2. 라벨 없는 줄 · ⚪ 줄 가운데 확인된 사실처럼 단정하는 줄 (코드 · 파일 내용, 수치, 바깥 세상 사실, '완료했다' 같은 보고)
3. 🔸 · 🔹 줄의 `[근거]` 를 직접 대조 — 파일:줄은 그 줄을 열어 보고, 명령 · URL 은 대화 기록에서 도구 출력을 찾아 본다

### 반려 기준
- 같은 질문에서 **1번째 반려**: 답을 숨기고 Stop 을 막아 **답 전체를 다시** 쓰게 합니다(맨 위에 `Revised:`).
- **2번째 반려부터**: 막지 않고 검토자 지적을 경고로 붙여 답을 보여 줍니다(끝없는 반복 방지).
- 판정은 `state/verdict_<세션>.json` 에 원자적으로 기록됩니다(tmp → fsync → replace).
  Stop 과 표시 훅 중 먼저 온 쪽이 잠금을 잡고 검토하고, 다른 쪽은 그 판정을 기다립니다(순서를 가정하지 않음).

### 안전장치
- 검토자 안에서는 우주모드 훅이 다시 돌지 않습니다(`WOOJU_NESTED`) — 무한 반복 방지.
- 검토자 실행 시 `ANTHROPIC_API_KEY` 를 넘기지 않습니다 — 선불 API 키가 아니라 구독 로그인으로 돌게.
- 검토가 실패 · 시간 초과(270초)되면 경고와 함께 **원래 답 전체를 보여 줍니다**(숨긴 채 잘리지 않게).

## 4. 설치

필요한 것: Claude Code(CLI, `MessageDisplay` 훅 지원 버전) · `claude` 명령이 PATH 에 있을 것 · Python 3.12 이상(f-string 표현식 안 백슬래시 사용).

```bash
# 1) 훅 폴더에 복사 (시험 파일이 이 경로를 기준으로 돈다)
mkdir -p ~/.claude/hooks
cp wooju_mode.py test_wooju.py ~/.claude/hooks/

# 2) ~/.claude/settings.json 에 훅 세 개 등록 (다른 훅 · 설정은 그대로 둔다)
python ~/.claude/hooks/wooju_mode.py install

# 3) 오프라인 시험 (진짜 검토자를 부르지 않는다)
cd ~/.claude/hooks && PYTHONIOENCODING=utf-8 python test_wooju.py
#    → FAILS 0 / 26 · DISPLAY FAILS 0 / 18
```

`install` 은 설치 전 `settings.json` 을 백업하지 않습니다. 먼저 복사해 두는 것을 권합니다.
끄려면 `settings.json` 에서 `wooju_mode.py` 가 든 훅 항목 세 개를 지우면 됩니다.

그 밖의 명령:
- `python wooju_mode.py report` — 프로젝트별 위반 · 검토 판정(통과 · 1차 반려 · 2차 반려 · 검토 실패) 집계
- `python wooju_mode.py measure` — 과거 대화 기록에 돌려 숫자 · 파일 근거 위반 비율 측정

## 5. 한계
- 형식과 추적 가능성만 봅니다. 근거가 있는 틀린 해석은 검토자가 못 잡을 수 있습니다.
- A · C 답마다 검토자(Opus)가 한 번 돌아 **답이 보이기까지 20~30초** 더 걸리고, 그만큼 구독 사용량이 듭니다.
- 이미지(스크린샷)에서 읽은 숫자는 글자 대조가 안 되어 검사를 건너뜁니다.
